51  // A quick description of how the sparse image data are currently stored:
52  // * The data are either after the image data within the same file if extension is .msf, or
53  // in a separate file with the .sdat extension if the image extension if .msh
54  // * The image header must store the fields defined in lib/image/sparse/key.h
55  // These are currently verified on construction of the BufferSparse class. This proved to
56  // be simpler than trying to verify class matching on every interaction with the handler
57  // using templated functions.
58  // * The raw image data consists of unsigned 64-bit integer values. These values correspond to
59  // an offset from the start of the sparse data (wherever that may be) to the sparse data
60  // stored for that particular voxel.
61  // * Wherever sparse data for a voxel is stored, the data begins with a single unsigned 32-bit
62  // integer, which encodes the number of elements in that voxel. The following data is then
63  // a raw memory dump of that many instances of the relevant class type.
64  // * When a sparse image is created for writing, a single unsigned 32-bit integer value of 0
65  // is written at the start of the sparse data. This is done so that uninitialised voxels
66  // can have their raw image value set to 0, and if they are dereferenced, the handler will
67  // indicate that there are zero elements for that voxel.
68  // - Note however that nulling all image data on image construction is NOT currently handled
69  // by either the Handler::Sparse class nor the Image::BufferSparse class. The programmer
70  // is responsible for this initialisation for the time being.
71  // * The handler does not attempt any type of endianness conversion of the sparse data, so the
72  // systems that read/write the image files must have the same endianness. Since this can't
73  // be determined from the sparse data alone, the relevant Image::Format instead enforces
74  // the endianness of the image data to be native, and assumes that the sparse data has
75  // the same endianness. If the endianness does not match, the file won't open.
