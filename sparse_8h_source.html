41  // A quick description of how the sparse image data are currently stored:
42  // * The data are either after the image data within the same file if extension is .msf, or
43  // in a separate file with the .sdat extension if the image extension if .msh
44  // * The image header must store the fields defined in lib/image/sparse/key.h
45  // These are currently verified on construction of the BufferSparse class. This proved to
46  // be simpler than trying to verify class matching on every interaction with the handler
47  // using templated functions.
48  // * The raw image data consists of unsigned 64-bit integer values. These values correspond to
49  // an offset from the start of the sparse data (wherever that may be) to the sparse data
50  // stored for that particular voxel.
51  // * Wherever sparse data for a voxel is stored, the data begins with a single unsigned 32-bit
52  // integer, which encodes the number of elements in that voxel. The following data is then
53  // a raw memory dump of that many instances of the relevant class type.
54  // * When a sparse image is created for writing, a single unsigned 32-bit integer value of 0
55  // is written at the start of the sparse data. This is done so that uninitialised voxels
56  // can have their raw image value set to 0, and if they are dereferenced, the handler will
57  // indicate that there are zero elements for that voxel.
58  // * The handler does not attempt any type of endianness conversion of the sparse data, so the
59  // systems that read/write the image files must have the same endianness. Since this can't
60  // be determined from the sparse data alone, the relevant Image::Format instead enforces
61  // the endianness of the image data to be native, and assumes that the sparse data has
62  // the same endianness. If the endianness does not match, the file won't open.
