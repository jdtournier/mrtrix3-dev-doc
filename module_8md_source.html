1 Writing separate modules {#module_howto}
2 ========================
3 
4 The MRtrix [build process](@ref build_page) allows for the easy development of
5 separate modules, compiled against the MRtrix core (or indeed against any other
6 MRtrix module). This allows developers to maintain their own repository without
7 affecting the MRtrix core. The obvious benefit is that developers can keep
8 their own developments private if they wish to, and the MRtrix core can be kept
9 as lean as possible.
10 
11 A module simply consists of a separate folder, with its own `cmd/` folder,
12 and potentially its own `src/` folder if required. The
13 [build process](@ref build_page) is then almost identical to that for the
14 MRtrix core, with a few differences.
15 
16 The most relevant difference is how the build script is invoked. For a module,
17 compilation is started by invoking the MRtrix core's build script, from the
18 module's top-level folder. For example, if the MRtrix core resides in the
19 folder `~/src/mrtrix/core`, and the module resides in `~/src/mrtrix/mymodule`,
20 then the module can be compiled by typing:
21 
22  $ cd ~/src/mrtrix/mymodule
23  $ ../core/build
24 
25 For routine use, it is more convenient to set up a symbolic link pointing to
26 the MRtrix core's build script, and invoke that:
27 
28  $ cd ~/src/mrtrix/mymodule
29  $ ln -s ../core/build
30  $ ./build
31 
32 
33 Using a symbolic link as above has the added benefit that modules can be
34 daisy-chained together. If a new module is created that uses code from another
35 module's `src` folder, the dependencies can be met simply by creating a
36 symbolic link (called `build`) from the new module's folder and
37 pointing to the required module's build script (which will itself be a
38 symbolic link to the MRtrix core's build script). For example, if another
39 module is created in the folder `~/src/mrtrix/experimental`, which builds on
40 code in the module in `~/src/mrtrix/mymodule` (which has already been set
41 up as described above), then these commands will allow it to be compiled
42 directly:
43 
44  $ cd ~/src/mrtrix/experimental
45  $ ln -s ../mymodule/build
46  $ ./build
