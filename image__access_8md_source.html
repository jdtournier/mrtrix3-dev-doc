1 Accessing image data {#image_access}
2 ====================
3 
4 Access to data stored in image files is done via the dedicated classes and
5 functions outlined here. Most classes and algorithms included in MRtrix to
6 handle image data have been written using C++ templates to maximise code
7 re-use. They have also been written explicitly with multi-threading in mind,
8 and this is reflected in some of the design decisions. MRtrix also places no
9 restrictions on the dimensionality, memory layout or data type of an image - it
10 supports an arbitrary number of dimensions, any reasonable set of strides to
11 navigate the data array, and almost all data types available, from bitwise to
12 double precision complex.
13 
14 MRtrix provides many convenience template functions to operate on the relevant
15 classes, assuming they all conform to the same general interface. For
16 instance, there are simple functions to compute the number of voxels in an
17 image, to ensure the dimensions of two images match, to loop over one or more
18 images, to copy one image into the other, and more advanced functions to smooth
19 images or compute gradients.
20 
21 The basic architecture used in MRtrix is outlined below, along with an example
22 application to illustrate how the different pieces fit together. The various
23 classes and functions are then described in more detail.

27 Overview {#image_access_overview}
28 ========
29 
30 [Header]: @ref MR::Header
31 [Image]: @ref MR::Image
32 [Adapter]: @ref MR::Adapter
33 [Filter]: @ref MR::Filter
34 [Iterator]: @ref MR::Iterator
35 [Loop]: @ref MR::Loop
36 [ThreadedLoop]: @ref MR::ThreadedLoop
37 
38 MRtrix3 defines a [Header](@ref header_class) class representing the on-disk
39 attributes of an image. Accessing voxel data is done via the [Image](@ref image_class)
40 class, or via an [Adapter](@ref adapter_class) class providing a modified view of an
41 [Image](@ref image_class).
42 
43 Many functions in MRtrix3 are template calls that can operate on any object
44 that presents the expected interface (i.e. specific methods and attributes).
45 Some functions only require access to the _attributes_ of an image, not the
46 voxel intensities. For these functions, the template argument is typically
47 labelled `HeaderType`, and will accept [Header](@ref header_class),
48 [Image](@ref image_class) or [Adapter](@ref adapter_class) classes.
49 Other functions will also access image intensities; in such cases, the template
50 argument is labelled `ImageType`, and the function will accept [Image] and
51 [Adapter](@ref adapter_class) classes (i.e. not the [Header](@ref header_class)
52 class).
53 
54 The [looping functions](@ref image_loop) available in MRtrix3 fall into this
55 category, and illustrate the concept. These can be instantiated from a
56 `HeaderType` (since the image attributes are sufficient to construct the loop
57 object), but will operate on `ImageType` objects (since they will access the
58 voxel values).
59 
60 [Filter](@ref filter_class) classes are also available for common operations.

63 An example application {#image_example}
64 ======================
65 
66 This simple example illustrates the use of this functionality, in this
67 case to perform multi-threaded 3x3x3 median filtering of the input image into
68 the output image (similar to what the `MR::Filter::Median` filter does),
69 converted to `Float32` data type:
70 
71 ~~~{.cpp}
72 void run ()
73 {
74  // access the input image:
75  auto in = Image<float>::create (argument[0]);
76 
77  // obtain and modify the image header:
78  Header header (in);
79  header.datatype() = DataType::Float32;
80 
81  // create the output image based on that header:
82  auto out = Image::create (argument[1], header);
83 
84  // create a Median adapter for the input voxel:
85  std::vector<int> extent (1,3);
86  auto median_adapter = Adapter::make<Adapter::Median> (in, extent);
87 
88  // perform the processing using a simple multi-threaded copy:
89  threaded_copy_with_progress_message ("median filtering", median_adapter, out);
90 
91  // done!
92 }
93 ~~~

96 Header {#header_class}
97 ======
98 
99 The [Header] class contains modifiable information about an Image as stored
100 on disk - whether this image already exists or is about to be created. This
101 includes:
102 
103 - image dimensions
104 - image spacing (i.e. voxel sizes)
105 - image strides
106 - data type
107 - the format of the image
108 - files and byte offsets where the data are stored
109 - the DW gradient scheme, if found.
110 - any other image header information, such as comments or generic fields
111 
112 The [Header] is designed to be copy-constructible (from another [Header] or any
113 [Image] or similar class) so that all copies are completely independent.
114 It is used as-is to retrieve or specify all the relevant information for
115 input and output images, and is designed to be instantiated from existing images,
116 modified to suit, and used as a template for the output image. Instantiating a
117 Header does _not_ load the image data - only when an [Image] is instantiated
118 (whether directly or from a previously opened [Header]) is the data actually made
119 available.
120 
121 For example:
122 ~~~{.cpp}
123 // open an existing image, as specified by the first argument:
124 auto header = Header::open (argument[0]);
125 
126 // modify as necessary:
127 header.set_ndim (3);
128 header.datatype = DataType::Float32;
129 
130 // create an output Header, according to the second argument.
131 // this header is then ready to be accessed by an Image:
132 auto header_out = Header::create (argument[1], header);
133 ~~~

137 Image {#image_class}
138 =====
139 
140 The [Image] class provides access to the image data, and most of the information
141 provided by the [Header]. This includes specifically:
142 
143 - image dimensions
144 - image indices (current position)
145 - image spacing (i.e. voxel sizes)
146 - image strides
147 - the DW gradient scheme, if found.
148 - generic fields
149 
150 The [Image] class is designed to be lightweight and copy-constructable, so
151 that all copies access the same image data. In essence, all copies of the
152 [Image] share a common [Header] via a shared pointer. This is essential for
153 multi-threading, by allowing multiple threads to each have their own
154 instance of an [Image], so that they can all concurrently access the image
155 data without affecting each other (although threads do need to ensure they
156 don't write to the same voxel locations concurrently - see
157 @ref multithreading for details).
158 
159 The [Image] class can be used to access on-disk data (existing or newly
160 created images), or on-RAM temporary (scratch) data. The developer can
161 request _direct IO_ where this can benefit performance, which means
162 the data will be accessed in RAM using the same type as requested in the
163 `ValueType` template argument (this will involve preloading if the on-disk
164 datatype does not match). Also, the in-RAM layout (_strides_) of the data
165 can be specified by the developer, to ensure contiguity of the data in RAM
166 in situations where this can affect performance. In general, the [Image]
167 class will try to access the data via memory-mapping where possible,
168 reverting to a preload strategy otherwise (for example, the data are stored
169 across too many files, or the developer has requested a data layout that
170 doesn't match the image on disk).
171 
172 For example:
173 ~~~{.cpp}
174 // open an existing header and create instantiate an [[Image]] to access the
175 // data as float:
176 auto header = Header::open (argument[0]);
177 auto in = header.get_image<float> (header);
178 
179 // open another existing image directly, without opening the Header first
180 // here, the data are accessed as bool:
181 auto mask = Image<bool>::open (argument[1]);
182 
183 // create output image based on input image's on-disk header:
184 auto out = Image::create (argument[2], header);
185 
186 // create an output Header first, then the image.
187 // this time, the output image uses the in-RAM header from the mask image:
188 auto header_mask = Header::create (arguemnt[3], mask);
189 auto mask_out = header_out.get_image<bool> (header_mask);
190 
191 // open another image with fast (direct) IO, with data contiguous along
192 // axis 3 (the volume axis):
193 auto image = Image<uint32_t>::open (opt[0][0]).with_direct_IO (3);
194 ~~~

198 Adapter {#adapter_class}
199 =========
200 
201 [Adapter] classes provide a modified view into the data held by another
202 [Image]. This may involve on-the-fly computation of derived values (e.g. the
203 neighbourhood median, a smoothed version of the data, etc.), or access
204 to selected portions of the data (e.g. a ROI, etc.). They are written to
205 have a semantically identical interface to the [Image] class, so that they
206 can be used in place of an [Image] in many of the algorithms (e.g. the
207 looping functions).
208 
209 For example:
210 ~~~{.cpp}
211 // open an existing image:
212 auto in = Image<float>::open (argument[0]);
213 
214 // create an Adapter::Subset to access an ROI:
215 std::vector<int> from = { 10, 10, 20 };
216 std::vector<int> dim = { 5, 5, 5 };
217 auto roi = Adapter::make<Adapter::Subset> (in, from, dim);
218 
219 // use the adapter like any other Image:
220 threaded_copy (roi, output_image);
221 ~~~

227 Filter {#filter_class}
228 ========
229 
230 [Filter] classes are used to implement algorithms that operate on a whole
231 image, and return a different whole image. Typical usage involves creating an
232 instance of the filter class based on the input image, followed by creation of
233 the output image using the filter itself as the template [Header]
234 (it derives from [Header]). Processing is then invoked using the filter's
235 `operator()` method.

239 Loop & ThreadedLoop {#image_loop}
240 =======================
241 
242 MRtrix provides a set of flexible looping functions and classes that
243 support looping over an arbitrary numbers of dimensions, in any order
244 desired, using the [Loop] and [ThreadedLoop] functions and associated classes.
245 These enable applications to be written that make no assumptions about the
246 dimensionality of the input data - they will work whether the data are 3D or
247 5D.

250 Iterator {#iterator_class}
251 ==========
252 
253 The [Iterator] class is a simple structure containing basic information related
254 to an image. This includes:
255 
256 - image dimensions
257 - image indices (current position)
258 
259 It is used as a placholder for the looping functions, in cases where the loop
260 shouldn't operate on an [Image] directly.
